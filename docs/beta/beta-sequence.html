The constraint change, stated plainly

Hard rule #1 becomes: "Everything shipped is generated from code in this repo — procedurally at runtime, or baked from a committed generator script. No third-party assets, ever, and nothing derived from any original 1995 game."

It gets written in the same commit as the first baked sprite, never before — until then the old rule is still literally true, and a repo that documents a future state is as dishonest as one that documents a past one. Three files move together: the repo's CLAUDE.md, the parent CLAUDE.md, and the README asset note. Rules #2 through #4 — never the original name, MIT only, child-friendly tone — are unchanged and remain absolute.

The nine phases

Ordered by dependency. Sprites moved into the critical path rather than after the first post, on your call that sprite quality matters more to the game than the purity of the pitch — and they sit before the capture so the video shows final art. The procedural hook isn't lost, it's reframed: a scripted, fully reproducible Blender bake pipeline is its own r/godot story, as long as the post describes it accurately.

M6Ready

Feel pass

Medium

Everything here ships toggleable — the same juice that reads as great feel to one player reads as nausea to another.

  • Enemy pain states and hit-stop: the biggest single feel win available.
  • Per-weapon view-kick and muzzle flash.
  • Hit-confirm: enemy flash plus an impact layer.
  • Enemy infighting — stray enemy fire damages other enemies. Cheap, spectacular, and more period-accurate.
  • Boost feedback: FOV kick and audio swell.
M7Iterative

Sprite pipeline

MediumRule change lands here

Priority order: the player ship first — most looked at, and what procedural generation is worst at — then the three bosses, then the hulk and turret if they don't read at fog distance.

  • Concept prompt targeting era and genre traits, never a specific 1995 game's artwork.
  • Image generation for look development only — concept art a human judges.
  • Model in Blender via MCP, scripted so it's reproducible as Python, not a binary.
  • Sixteen-angle turnaround plus pain and death frames.
  • Quantise to the game palette; kilobytes per enemy.
  • Verify in-engine at fog distance. If it doesn't beat the generator, it doesn't ship.

Design intent: imitate the era, land somewhere distinct. Each subject gets one or two deliberate departures — silhouette language, a signature colour, a structural motif — rather than chasing maximum period fidelity. It should read as your game.

Why clearing context is safe here

None of these sessions needs the previous session's transcript. Each needs the previous session's committed code plus PLAN.md's ledger — which is exactly what the handoff writes down: commit with the phase in the message, update the Phase M ledger row, append the CLAUDE.md session log with phase, gate result, and what's next, then note anything surprising the next session would otherwise rediscover.

Starting fresh: read the last session log and the Phase M row, state your position out loud, verify the previous gate if it was recorded as partial, and begin. Don't re-derive the plan — it's written down.

Parallel track · starts this week, yours alone

Account warm-up

Reddit's norm is roughly nine parts genuine participation to one part promotion, with karma and account-age gates on top. A cold account posting a link risks a shadowban — which costs the launch silently, with no error message and no appeal in time to matter.

So starting now, independent of every phase: participate in r/godot for real. Procedural generation, web export, and WebGL shader-compile behaviour are all things you can genuinely help people with after this project. Ten minutes a day, weeks of lead time, and no amount of engineering shortens it.
