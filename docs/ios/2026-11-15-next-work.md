# VOIDLINE: next work for web, iOS and controllers

_Written 2026-11-15, after PR #25 (TestFlight packaging, silent-switch setting, rename). A
list for a planning session to turn into an implementation plan. Nothing here has been run on
real hardware: the items marked **hypothesis** are guesses until a device session settles them._

Context: the game is VOIDLINE ("VOIDLINE: Sector Zero" on the store). Controller support from
PR D is `scripts/pad_watch.gd` (hot-plug), `scripts/pad_glyphs.gd` (button names by layout) and
`scripts/input_setup.gd` (bindings). The iOS build is `build_ios.sh`, specified in
`docs/ios/2026-11-15-testflight-build-spec.md`, checked by `docs/ios/TESTFLIGHT.md`.

## 2. Controller (8BitDo SN30 Pro and any Bluetooth pad)
1. **On-device PAD TEST screen** in SETUP > CONTROLS: pad name, detected layout, live button
   and axis values, stick position. Highest value, because items 2 and 3 can only be settled on
   a device and this settles them in one session. Touches `overlays.gd`, `pad_glyphs.gd`.
2. **Layout override:** BUTTON LABELS: AUTO / XBOX / NINTENDO. `PadGlyphs.layout_for` guesses
   from the pad's name string; the names iOS and browsers report for the SN30 Pro are
   unverified (**hypothesis**).
3. **Trigger mapping check.** The SN30 Pro's ZL and ZR are digital. `input_setup.gd` binds fire
   and boost to trigger axes at `axis_value 1.0`, plus the R and L shoulder buttons. Check on
   iOS, in Safari and in Chrome that ZR fires and ZL boosts, as `TESTFLIGHT.md` claims
   (**hypothesis**).
4. **Stick tuning.** `player.gd:191-197` hard-codes a 0.15 deadzone, a linear response and no
   pad sensitivity setting. Add pad sensitivity and deadzone, possibly a response curve, and
   check for drift, since the stick steers the whole game.
5. **Button remapping.** Nothing exists today. An accessibility feature and a likely beta
   request. Extends `input_setup.gd`, persists in `game_state.gd`, needs pad-navigable UI.
6. **Auto-enable on web and desktop.** The GAMEPAD toggle is opt-in there (K6), so a web player
   with a pad has to find it in SETUP. Browsers only expose a pad after its first button press,
   so a "controller detected, turn on?" prompt is the likely design.
7. **Menu parity:** check every panel (Bay, tally, episode cards, difficulty, SETUP tabs) can be
   operated by pad alone, with no touch or mouse.
8. **Optional, low priority:** rumble, a second pad, Joy-Con. The SN30 Pro has no rumble.

## 3. iOS
1. **Run `./build_ios.sh archive` and `upload` on the Mac.** They have never run; the
   `xcodebuild` flags may need adjusting.
2. **The full device pass** in `docs/ios/TESTFLIGHT.md` on an iPhone and an iPad, with the pad.
   This includes SETUP > SOUND > SILENT SWITCH MUTES, which has only been tested as logic.
3. **Renderer risk:** the game uses GL Compatibility on iOS. How Godot 4.7 runs GL on current
   iOS is unconfirmed. Check shader-compile hitches and the palette LUT on an A-series GPU.
4. **Performance:** boot, first flight, L8 and L9 frame rates, a long-session thermal check, and
   120 Hz. Compare against `tests/perf_baseline.md`.
5. **App lifecycle:** audio after a phone call or Siri interruption, backgrounding mid-boss,
   CONTINUE after a force-quit, and checkpoints under `user_data_backup`.
6. **Touch edge cases:** Dynamic Island and home indicator in both landscapes; iPad
   multitasking (the plist is full-screen only).
7. **Beta logistics:** `docs/ios/BETA_REVIEW.md` still needs a real feedback email and contact.

## 4. Web
1. **Controller on web:** test in Chrome, desktop Safari and iPad Safari with the SN30 Pro.
   iPad Safari is the browser people will actually use with a pad.
2. **Add to home screen:** the PWA preset is off and a prompt helper exists. A standalone
   install would match the iOS feel.
3. **After the rename,** confirm the web shell, link card and preview tags show the new name on
   a deployed preview.
4. **Analytics:** `web/privacy.html` lists exactly four counters. Any new counter, such as
   "controller connected", means updating that page.

## 5. Tests and CI
- **Fake gamepad test for `tests/web_check.mjs`:** override `navigator.getGamepads` in
  Playwright to cover connect, menu navigation and pause-on-disconnect on web. CI has no
  controller coverage today.
- **Smoke tests** for the layout override, deadzone and remap persistence.
- **CI maintenance:** the Node 20 deprecation warning is cosmetic for now.
