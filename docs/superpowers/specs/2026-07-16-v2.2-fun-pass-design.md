# VOID RUNNER V2.2 — "The Fun Pass" Design Spec

**Date:** 2026-07-16
**Status:** Approved by John (Sections 1–3 explicitly; L3–L5 decisions delegated — "auto mode")
**Branch:** `v2.2-fun-pass`
**Scope source:** Brainstorm of 5 ideas; John picked all but the online daily-run/leaderboard idea,
with one overriding constraint: *the game must not bloat and must keep running smoothly* —
especially the nothreads WebGL build on Netlify.

---

## 0. Goal

Make VOID RUNNER as fun for a new generation as the '95 DOS games were, along four axes:

| Phase | Feature | Fun axis |
|---|---|---|
| **L1** | Impact & Gibs ("juice") | Moment-to-moment feel |
| **L2** | Style meter + adaptive music | Performance feedback / audio drama |
| **L3** | Salvage & Upgrade Bay | Progression / retention |
| **L4** | Tab automap | Doom identity / orientation |
| **L5** | Branching side-spurs (cuttable) | Exploration payoff |

Phases ship **in order**, each with its own verification gate and commit. L5 is explicitly
cuttable if its one risky mechanism (ring-tracking snap) misbehaves.

**Out of scope (decided):** online leaderboards/daily runs/ghosts (idea #3), real-time
multiplayer, level editor, boss-rush mutators, wingman drone, photo mode.

---

## 1. The Performance Contract (applies to every phase)

1. **Perf gate:** `tests/perf_probe` must stay within the current baseline band
   (worst step ~2.7–6 ms, zero repeating spike classes) before a phase merges.
   A regression gets fixed or the phase gets cut — V2.1 discipline.
2. **Pooling only, hard caps:** all new visual objects come from pre-allocated pools
   (pattern: `shot_manager` pools). Gibs cap at 48 live chunks, oldest recycled.
   **Zero per-frame allocations** in any new system's steady state.
3. **Warmup rule:** every new material / sprite variant / light interaction registers in
   `game._start_warmup` (and `_web_load_and_warm`), or it does not ship. This is what keeps
   the WebGL first-use freeze dead.
4. **Dirty-draw rule:** new HUD/2D surfaces redraw only when their state changes
   (pattern: V2.1 Step 4 HUD layers). The automap costs zero when closed.
5. **Memory ceiling:** adaptive music renders once, behind the existing loading overlay.
   Fallback if the web build's memory grows noticeably: base loop + one additive combat stem
   instead of three full mixes.
6. **Code placement:** each feature is a sibling manager or an existing-file extension —
   `game.gd` (1,005 lines) gains **signal wiring only** (stays within a few dozen lines).
7. **Design-bloat rule:** small surfaces — 3 weapon marks, 6 ship upgrades, 3 music
   intensities, 4 style grades, ≤2 spurs/level. Those '95 DOS games were tight, not sprawling.
8. **Test discipline:** smoke test + warmup probe extend with each phase; any test that
   touches `user://records.cfg` or settings snapshots and restores them (existing pattern).

## 2. L1 — Impact & Gibs

**New file:** `scripts/gib_manager.gd` (sibling manager, wired to `enemy_manager` signals).

### Gibs
- Pool of **48** billboard `Sprite3D` chunks, hard cap, oldest recycled.
- Spawn counts: normal kill ~6, hulk ~12, boss phase/death ~20 (still capped globally).
- Textures: small procedural fragments from `sprite_gen` (3–4 shapes, 8–12 px), tinted to
  the dying enemy's palette, generated at level build, **registered in warmup**.
- Motion: outward burst + partial enemy-velocity inheritance, mild gravity (~14 u/s²),
  sprite spin (±6 rad/s), lifetime 1.6–2.4 s with shrink-out.
- **Collision = `PathGen.clamp_to_ring`:** each gib tracks its ring index the way enemies
  do; when the clamp displaces a gib, reflect the velocity component and damp ×0.45 —
  debris ricochets down the tunnel for near-zero cost.

### Hit-stop
- `Engine.time_scale` dip with **real-time** restore (unscaled timer; smoke test asserts
  restoration): normal kill 30 ms, hulk 50 ms, boss phase ~90 ms, boss death 250 ms slow-mo.
- 150 ms cooldown between stops so multi-kills stay punchy, not stuttery.

### Camera kick & shake
- Per-shot pitch kick (per-weapon strength) + proximity-scaled shake impulse from nearby
  explosions; spring-decay offset in `player.gd`, no allocations.
- **Settings gains a SCREEN SHAKE toggle** (accessibility), persisted with existing settings.

### Enemy hit-flash
- Plan A: `Sprite3D.modulate` bright flash ~60 ms (per-instance, no material compile).
- Plan B (if WebGL duplicates materials): `sprite_gen` pre-bakes a white silhouette frame
  per enemy type; flash = texture swap. Either way compile-safe.

### Player-side feedback (HUD dynamic layers)
- Kill-confirm crosshair tick.
- Directional damage arcs: `player.damaged` path gains a source-position parameter from
  `shot_manager`; screen-edge arc fades 0.4 s pointing at the shooter.

### Audio
- Reuse kill thump; add quiet procedural gib-bounce ticks (`audio_sys`), ≤2 concurrent.

### Verification
- Smoke test: kills produce active gibs → pool fully drains after lifetime; `time_scale`
  restored; new textures covered by warmup probe. Perf probe in band.

## 3. L2 — Style meter + adaptive music

### Style meter (presentation on the existing combo system — no new scoring mechanics)
- Grades by kill streak: **3 = RAD, 6 = STELLAR, 10 = COSMIC, 15 = VOID LEGEND.**
- HUD meter bar fills with kills, visibly drains over the 4 s combo window; grade name pops
  on threshold (dirty-cache layer). Grade-up = short procedural sting.
- Tally: one new line — peak style grade, +100 bonus per tier. No new records fields.

### Adaptive music
- `music_gen.render_loop` renders **three phase-aligned mixes** of the same song:
  CALM (bass/pads/sparse drums), COMBAT (full kit + lead), FRENZY (+arps/percussion).
  Same tempo & sample length → three `AudioStreamPlayer`s started together stay
  sample-locked; adaptivity = volume crossfade only. No runtime synthesis.
- **Intensity score lives in `audio_sys`** (placement rule), computed from existing data:
  nearby enemy count, `shot_manager` enemy-shot cache size, combo multiplier, arena-lock
  state. Rises instantly, decays after ~4 quiet seconds (hysteresis), crossfade ~1.2 s.
  Locked arena floors intensity at COMBAT; boss fights force FRENZY (no fourth mix).
- Garnish: big kills duck the music bus ~100 ms (makes hit-stop land harder).

### Verification
- Smoke test: three streams sample-identical length; intensity rises on spawns, decays
  after clear; zero audio rendering post-load. Perf probe in band. Web memory eyeballed
  against ceiling (fallback pre-spec'd).

## 4. L3 — Salvage & Upgrade Bay

### Currency: SALVAGE
- New drop kind in the existing `enemy_manager.drop_spawned` → `pickup_manager` pipeline.
- Drop rates: ~30% of kills (value 5), guaranteed on hulks (15) and turrets (10);
  boss = 50; secret caches include +25. Same magnet/collect radii as other pickups.
- Collected salvage accrues to `GameState.salvage_run`; **banked at the level tally** into
  persistent `salvage_bank` (records.cfg). Gauntlet: drops appear, bank at run end, no Bay
  mid-run.

### Per-run weapon marks ('95-DOS-games-authentic weapon powerups)
- Each weapon (NEUTRON / SCATTER / BOLT / MISSILE) has **MK I → II → III**.
- Cost: MK II = 60, MK III = 140 salvage. Bay purchases draw from the run's salvage
  first, then the persistent bank (one visible combined balance in the UI).
- Effects (multiplier layer, applied at fire time via a `GameState.weapon_stat()` accessor
  over the `WeaponDef` resources — the `.tres` files stay the single source of base truth):
  - NEUTRON: damage +35/+75%, fire interval −8/−15%
  - SCATTER: damage +30/+60%, +1/+2 pellets
  - BOLT: damage +35/+75%, projectile speed +15/+30%
  - MISSILE: splash radius +15/+25%, ammo cap +3/+5
- **Reset on `reset_run`** (new campaign = MK I). Persist across levels within a run.

### Persistent ship upgrades (records.cfg; bounded so difficulty stays honest)
| Upgrade | Ranks | Effect | Cost/rank |
|---|---|---|---|
| SHIELD CAP | 2 | max shields 100 → 120 → 140 | 120 / 260 |
| HEAT SINK | 2 | heat per shot −12% / −22% | 120 / 260 |
| ENERGY CELL | 2 | max energy +20 / +40 | 120 / 260 |
| MISSILE RACK | 2 | missile cap +5 / +10 | 120 / 260 |
| SALVAGE MAGNET | 1 | pickup magnet radius +50% | 180 |
| HULL PLATING | 1 | wall-bounce damage −30% | 180 |

- Max caps move behind accessors (`GameState.max_shields()` etc.); the `MAX_*` consts
  remain the base values.
- **Score is never multiplied by upgrades** — ranks (S/A/B/C) stay comparable.
- Economy target: one full campaign clear earns ~400–600 salvage (tune in playtest).

### Upgrade Bay UI
- Lives **only** on the briefing screen (`overlays.gd`): a Bay panel listing weapon marks
  and ship upgrades, salvage balance, keyboard/mouse (+ optional gamepad) navigation,
  buy = instant apply. One place, no shop sprawl.

### Verification
- Smoke test: salvage drop → collect → bank round-trip; MK II purchase changes computed
  damage via the accessor; persistent rank survives save/load; records snapshot/restore;
  gauntlet unaffected by marks. Perf probe in band (pure logic + one overlay panel).

## 5. L4 — Tab automap

**New file:** `scripts/automap_display.gd`, rendered **inside the 320×200 game SubViewport**
(chunky + dithered for free), toggled by a new `automap` input action (Tab; gamepad Back
when gamepad enabled).

- **Opening the map pauses the game** (reuses pause plumbing; constant-forward flight makes
  a live map lethal, and pausing is the safe, child-friendly, Doom-authentic call).
- Top-down XZ projection, **north-up fixed** with a blinking player arrow; fit-to-explored
  bounds with +/− zoom steps.
- Explored = rings 0 → furthest-visited (+2 lookahead); spurs (L5) appear once entered.
- Markers: tunnel polyline thickened by ring half-width (tunnel/arena/boss visually
  distinct), locked arenas (lock glyph), found secrets (S), discovered exit portal,
  seen crushers (hazard tick). Nothing undiscovered is shown. Palette colors only.
- **Dirty-draw:** polyline/marker arrays rebuild only when the explored range or markers
  change; `_draw` runs only while open (game is paused, so nothing competes). Zero cost
  closed.

### Verification
- Smoke test: headless open/close asserts pause/resume and draw-data coverage of explored
  rings. Screenshot probe captures a map frame for the 1995-believability check.

## 6. L5 — Branching side-spurs (campaign-only, cuttable)

**Scope guard:** dead-end spurs, **not** rejoining loops; campaign levels 2+ only (never
boss levels); 1–2 per level. Rides V2.1's full-prebuild (no streaming interaction).
Gauntlet spurs deferred to backlog.

- **PathGen:** after main generation, `_add_spurs(count)` picks non-final arena rings and
  grows 8–16-ring runs branching 60–110° off heading, slightly narrower (HW ~6), ending in
  a small turnaround cache chamber (HW ~14). Spur rings **append to the same rings array**
  with `spur_id` + entry-ring metadata — `clamp_to_ring`, `corner`, per-ring math unchanged.
- **Entry:** a visible side-hatch on the arena wall (reuses door material family, distinct
  accent tint), auto-opens on approach ('95-DOS-games-style doors). Interior gets a dimmer lighting mood.
- **The one risky mechanism — ring-tracking snap:** `nearest_ring` relies on index
  locality, and a doorway crossing jumps indices (arena ~40 → spur ~200). A doorway trigger
  volume snaps the player's tracked ring index on crossing (both directions) with
  hysteresis. Enemies spawn only inside spurs with spur indices (they stay clamped there).
  Radar is position-based — unaffected.
- **Reward:** cache chamber holds a salvage bundle + pickups, occasional plasma bomb;
  briefing gains "OPTIONAL: SUPPLY CACHE DETECTED"; tally gains "CACHES n/m"; +300 score
  each. Automap draws entered spurs.
- **Cut line:** if the snap is flaky in playtest, V2.2 ships L1–L4 and spurs move to the
  backlog. This is a pre-agreed outcome, not a failure.

### Verification
- Smoke test: player ring continuity crossing the doorway both ways; spur enemies remain
  clamped inside; cache collect fires tally counter; boss/gauntlet levels assert zero
  spurs. Perf probe on a spur-bearing level stays in band.

## 7. Cross-cutting verification & ship gates

1. Per phase: headless import clean → boot clean → extended smoke test green → perf probe
   in band → web export builds → **one commit per phase** on `v2.2-fun-pass`.
2. John's playtest gates the branch → `main` merge (Netlify auto-deploys `main`).
3. Records/settings snapshot-restore in every test that touches them.
4. Docs de-drift at the end: CLAUDE.md §6 session log, PLAN.md ledger, memory files.
