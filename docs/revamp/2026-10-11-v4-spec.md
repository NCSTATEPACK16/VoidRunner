### How to work: an orchestrator with Sonnet subagents
The session that reads this is the **orchestrator**. It does not write most of the code
itself. It breaks each PR into steps, hands each step to a **Sonnet subagent** (the `Agent`
tool with `model: "sonnet"`), and owns integration, the gates, and the PRs.

- **One subagent per step, sized to one commit.** The step plans in §5–§7 are already split
  that way. Give each subagent:
  - the step's section of this file, quoted in full;
  - the files it will touch;
  - the hard rules (§1, below);
  - §9's gotchas;
  - the gate it must pass before reporting back. That gate is at least the smoke test (§4.1),
    plus any probe the step names.
- **Run steps that touch different files in parallel**, each in its own worktree
  (`isolation: "worktree"`). Steps that touch the same files (`game.gd`, `smoke_test.gd`) run
  one after another on the branch. In a worktree, copy `bin/Godot_v4.7-stable_linux.x86_64`
  from the main checkout and run `--import` before testing.
- **Subagents don't commit, push, open PRs or merge.** They leave a working-tree diff and a
  short report:
  - what changed;
  - the test output lines;
  - anything they couldn't finish.
- **The orchestrator reviews every diff before committing it.** Read it against the spec and
  the hard rules, then run the gates, commit, and push. If a subagent's result fails a gate,
  send it back to that subagent (SendMessage) with the failing output. Don't patch over it
  silently.
- **Rendered and web gates (§4.3–4.4) are the orchestrator's,** run once per PR on the
  integrated branch. Subagents may run them for their own step when the step changes visuals.
- **Ask the user only for a decision the spec doesn't cover.** §7 lists the open ones, each
  with a default.

### Merging and the branch
- **Merge each PR yourself** with the GitHub MCP `merge_pull_request` tool (method "merge"),
  once every gate passes and the Netlify deploy preview is green. Check the preview with
  `gh api repos/NCSTATEPACK16/VoidRunner/commits/<full head sha>/status`, watched with a
  polling loop or Monitor, never a bare sleep.
  - `merge_pull_request`'s `expectedHeadSha` needs the full 40-character SHA.
  - Production deploys of `main` post no status; only PR previews do.
- **After each merge,** restart the branch from `origin/main` and start the next PR. Don't wait
  for playtests.
- **The branch is `claude/game-revamp-dos-aesthetic-vdk6fy`.** Restart it with:

  ```sh
  git fetch origin main && git checkout -B claude/game-revamp-dos-aesthetic-vdk6fy origin/main
  ```

  Push with `-u`. Use `--force-with-lease` only when replacing already-merged history.

### Facts the next PRs build on
- **Title (PR #15), in `overlays.gd`:**
  - The `start` panel has two states, attract (`_start_open == false`) and the card row
    (CONTINUE / NEW GAME / GAUNTLET / SETUP).
  - The sector picker, DIFFICULTY, FLIGHT MANUAL and LAUNCH live in the `new_game` panel.
  - `START_SUBS` lists the panels whose BACK returns to the card row.
  - The SETUP card opens today's `settings` panel; v4d's SETUP window replaces that target.
  - The smoke test's TITLE block covers it all.
- **Mini-boss and hub room:**
  - **`PathGen.mid_arena()`** returns the kill-locked arena nearest mid-sector. In L2, L5 and
    L8 the mini-boss holds it, and `game._miniboss_arena` remembers it. v4c's hub is the same
    room.
  - **The mini-boss** is `EnemyManager.boss` with `miniboss: true`. It counts toward its room's
    tally. Its death emits `miniboss_killed`, and the checkpoint carries `miniboss_down`.
  - Since PR #16, a resume with the mini-boss down but its room not yet cleared adds it to
    `_arena_kills`.
- **Checkpoints** (`game._checkpoint_data` / `_apply_resume`, normalised in
  `GameState.normalize_checkpoint`) take optional fields.
  - Add each new field to `normalize_checkpoint` with a default.
  - PR #16 added `secrets_found` (rings), `caches` (spur ids) and `props_gone` (prop ids). A
    resume re-applies them, so nothing pays out twice.
  - `_int_list()` normalises JSON floats to ints.
- **`SpurManager`** has `collected_ids()` / `mark_collected(ids)` (PR #16). v4c's key and switch
  spurs must keep supply caches working through these.
- **`PropManager`** props carry a spawn-order `id`, with `gone_ids()` / `remove_ids()`. v4c's
  generator, reactor and anchor kinds must keep ids stable per level seed.
- **`PickupManager.add_station(pos, kind, refill := false)`.** Only `refill` stations (the main
  bosses') come back at boss phase changes. Keycards and pods use `refill = false`.
- **`EnemyManager.announced(text)`** puts a line on the HUD. The HUD shows one line at a time
  until v4d's message log.
- **Stat signals** (`shields_changed` / `energy_changed` / `heat_changed`) fire only on change
  since PR #16. Don't rely on a per-frame emit.
- **SpriteForge (PR #17):**
  - The 7 extra angle copies of each model are RenderingServer instances (`_mesh_parts`, freed
    after readback).
  - The boss sheet bakes on the first `sprite_set()` of a boss model, which happens during a
    level load.
  - **v4c's new `OBJECTS` sheet (64 px)** should follow the same pattern: bake on first use
    during a level load, not at boot, unless it's under ~100 ms on software GL.
  - Measure with an A/B against `main` (§4.3) and log it.
- **Web numbers today (SwiftShader, this container):**
  - boot bake about 1.3–1.5 s;
  - title up about 8.2–8.5 s;
  - L1 first flight about 22 s, with the scripted waits.
  - The container's speed varies day to day, so always A/B against `main` rather than compare
    with old numbers.

## 3. Setup in a fresh container

- **Godot** isn't committed (`bin/` is gitignored). Run `./build.sh` once: it downloads
  `bin/Godot_v4.7-stable_linux.x86_64` and the web templates into
  `~/.local/share/godot/export_templates/4.7.stable`, then exports.
  - Afterwards use `G=bin/Godot_v4.7-stable_linux.x86_64` and run `$G --headless --import`.
  - Repeat the import after adding any `class_name` script.
- **After any export,** run `git checkout -- scripts/build_info.gd web/vr_shell.html`; the
  export stamps them.
- **Rendered runs:**

  ```sh
  xvfb-run -a -s "-screen 0 1280x800x24" $G --rendering-driver opengl3 --resolution 960x600 <scene>
  ```

  The GLES3 pass uses `opengl3_es`.
- **Probes write PNGs** to `VR_SHOT_DIR`.
- **Expected noise you can ignore:**
  - ALSA `ERR_CANT_OPEN` / "status < 0" lines (no sound device in the container);
  - `ERR_TUNNEL_CONNECTION_FAILED` (analytics) in Chromium.
- **Playwright** is installed globally (`/opt/node22/lib/node_modules/playwright`). Chromium is
  at `/opt/pw-browsers/chromium`. Don't run `playwright install`. `tests/web_check.mjs` finds
  both.
- **The live site isn't reachable** from the container (the proxy blocks it). Verify deploys
  through the GitHub commit status only.

## 4. Gates for every PR

1. **Smoke and probes.**
   - Run `timeout 1500 $G --headless tests/smoke_test.tscn`. It must print
     SMOKE TEST COMPLETE with 0 SCRIPT ERROR. Always wrap it in `timeout`: a parse error or a
     failed assert leaves headless Godot hanging.
   - It takes about 10 minutes, so run it in the background and poll the log.
   - The warm-up probe and `tests/soak_probe.tscn` complete. PR B replaces the soak probe with
     `campaign_probe`.
2. **Perf, headless:** L8 rail ×2, L9 rail, gauntlet ×2, dense L8 ×2.
   - The worst step must be under 8 ms. A one-off spike gets a rerun and is reported honestly.
   - **Rendered dense L8:** the `[draw]` peak stays at most ~105 (today 83–95).
   - The rendered average frame time depends on the container. Compare it with an alternating
     A/B against a `main` worktree, never with old logs (on 2026-10-10, `main` itself measured
     27 ms against 17–18 ms logged a week earlier).
   - Script:

   ```sh
   # perf_runs.sh <outdir>   (run from the repo root)
   G=bin/Godot_v4.7-stable_linux.x86_64; out=$1; mkdir -p $out
   run() { name=$1; shift; env "$@" timeout 900 $G --headless tests/perf_probe.tscn > $out/$name.txt 2>&1
     echo "== $name"; grep -E "worst step|average step|\[fx\]|\[spike\]|COMPLETE|SCRIPT ERROR" $out/$name.txt; }
   run l8_a VR_PERF_RAIL=1 VR_PERF_LEVEL=7; run l8_b VR_PERF_RAIL=1 VR_PERF_LEVEL=7
   run l9 VR_PERF_RAIL=1 VR_PERF_LEVEL=8
   run gauntlet_a VR_PERF_RAIL=1 VR_PERF_GAUNTLET=1; run gauntlet_b VR_PERF_RAIL=1 VR_PERF_GAUNTLET=1
   run dense_a VR_PERF_DENSE=1 VR_PERF_LEVEL=7; run dense_b VR_PERF_DENSE=1 VR_PERF_LEVEL=7
   for r in 1 2; do env VR_PERF_DENSE=1 VR_PERF_LEVEL=7 VR_PERF_RENDERED=1 timeout 900 xvfb-run -a \
     -s "-screen 0 1280x800x24" $G --rendering-driver opengl3 --resolution 960x600 tests/perf_probe.tscn \
     > $out/dense_r$r.txt 2>&1; grep -E "worst step|\[draw\]|COMPLETE|ERROR" $out/dense_r$r.txt; done
   ```
3. **Rendered checks under xvfb:**
   - **The screenshot probe.** View the PNGs (upscale them with PIL to inspect) and read each
     `[shot]` draw count. The title shots are `shot_start`, `shot_start_menu` and
     `shot_new_game`.
   - **`tests/forge_probe.tscn`.** It saves the contact sheets and prints
     `[forge] baked in N ms` plus `[forge] boss sheet baked in N ms`.
     - For a bake A/B, add a `git worktree` of `origin/main`, copy `bin/` into it, run
       `--import`, then alternate runs.
     - For a pure refactor, also pixel-compare the contact sheets: `ImageChops.difference`
       must have a bbox of `None`.
   - **FX parity.** `tests/fx_parity_probe.tscn` prints FX PARITY OK on both `opengl3` and
     `opengl3_es`.
   - **GLES3 shaders.** An `opengl3_es` screenshot-probe pass shows 0 shader errors.
4. **Web.** Export with `./build.sh` (or `$G --headless --export-release "Web" dist/index.html`),
   then run:

   ```sh
   node tests/web_check.mjs <outdir> dist
   ```

   - It plays the PRESS START flow: notice → PRESS ENTER → card row → NEW GAME → LAUNCH →
     briefing LAUNCH → 8 s of fire.
   - It fails on SCRIPT ERROR, SHADER ERROR or a page error. The known pointer-lock race is
     ignored.
   - Note the bake, title-up and first-flight lines.
   - **If a PR changes the menus, update the key presses in `web_check.mjs` in the same PR.**
5. **Docs**, in each PR's last commit:
   - the v4 plan's progress section;
   - the re-audit progress table;
   - `tests/perf_baseline.md`, with the bake table kept current.

## 7. PR C: beta polish (web first, then Xcode)

The user is preparing an App Store beta: "Web needs to be polished then we will do Xcode work".

- **Pointer-lock race.**
  - When a level load ends after the keypress's activation window, the browser refuses
    `requestPointerLock` and logs an uncaught page error. The next click captures the mouse.
  - Fix: request capture only in response to a click or keypress during PLAYING, and handle
    the refusal quietly. If Godot's JS throws regardless, add a narrow `unhandledrejection`
    filter in `web/vr_shell.html`.
  - Then remove the ignore in `tests/web_check.mjs`.
- **Bake cache across visits (optional).**
  - Save the baked atlases to `user://` (IndexedDB on web), keyed by `BuildInfo.ID` and a bake
    version; a returning visitor skips the bake.
  - Measure the decode cost against the bake first. Do this only if it saves at least 300 ms on
    SwiftShader.
- **Engine download size: the user's decision.**
  - The engine is 39.5 MB (about 10 MB gzipped); the game pack is 0.56 MB.
  - Shrinking it needs a custom export template with unused modules disabled. That means a long
    emscripten build and a hosted template, because Netlify can't compile it.
  - **Ask the user** before starting. **The default is to skip it.**
- **Leave LightRig as is.** The review suggested global uniforms. As far as anyone has checked,

## 10. Gotchas (give these to every subagent)

- **Test variables.** `smoke_test.gd`'s `_run()` is one long function. Declaring a local that
  is already in scope is a parse error ("already a variable named …"), and the headless run
  then hangs until its `timeout`. Prefix new locals per block (`hl_`, `cl_`, `rv_`, …), and
  parse-check before a long run:

  ```sh
  $G --headless --check-only --script res://tests/smoke_test.gd
  ```

  This works for tests only. Game scripts fail it, because `--script` mode has no autoloads.
- **Asserts hang, too.** A failed `assert` in headless Godot stops the run without exiting. Poll
  the log for `SCRIPT ERROR` rather than waiting for the process.
- **Type inference.** `:=` can't infer from a call on the untyped `game` node in tests
  (`var x: int = game.path.mid_arena()`), nor from Dictionary or Variant access.
- **Placing the ship in a probe.** Putting it past sealed bulkheads makes
  `PlayerShip._door_collide` shove it back to the first one. Open the earlier doors first, as a
  resume does.
- **Smoke-test isolation.** Later sections can inherit a kill streak (`GameState.combo`), enemy
  shots, or a resumed checkpoint from earlier ones. Reset what a check depends on.
- **Frame-time-dependent asserts.** One frame of flight after a level rebuild can be long.
  Scale distance checks by `get_process_delta_time()` (see the resume check in the CHECKPOINT
  block).
- **HUD messages.** Several in one frame overwrite each other until v4d's log. Order the emits
  (`_kill` emits `miniboss_killed` before `enemy_killed`).
- **Netlify** previews take a few minutes. Rendered perf on llvmpipe has rare one-off stalls;
  rerun and A/B before calling anything a regression.
